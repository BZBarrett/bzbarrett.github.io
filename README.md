# Bing Zhou website

Static HTML, CSS and JavaScript, suitable for GitHub Pages. No build or server-side API keys are required.

## Local preview

From this directory, run `python3 -m http.server 8770 --bind 127.0.0.1` and open <http://127.0.0.1:8770/>. Journey Studio is at `/journey-studio.html`, also linked from Wanderlust. Use HTTP/HTTPS, not `file://`, because the site uses JavaScript modules and local data fetches.

## Journey Studio

- The journey list shows every saved journey with its color, a visibility checkbox, an edit-name button and a delete icon. Click the name to edit that journey; independently check any subset to show on the map. All/None controls change visibility together. Hidden journeys remain editable and saved, and their playback is stopped/hidden. Deletion asks for confirmation; removing the last journey creates an empty one. Previous all/current-only map preferences migrate to per-journey visibility.
- Create multiple journeys, search/select endpoints or choose them using the crosshair icons beside Starting point and Destination (Escape cancels), compare route options and append segments. Searching fits the selected route option, switching alternatives fits that alternative, and saving or replacing a segment fits the saved route. Distant journeys, saved points and unselected alternatives do not affect these bounds. Selecting a journey fits its own visible routes and places; an empty journey preserves the current camera. A pending map startup or canvas resize keeps the requested route framing. Flight bounds follow continuous longitudes across the date line, including long connecting routes. Long routes in globe view use a spherical center and check the projected route against the visible map area, so polar arcs are not framed using a longitude/latitude rectangle. Every segment can have car, train, plane or walking metadata, important endpoints, notes and departure/arrival dates. Date inputs accept `MM-YYYY` directly (for example `11-2026`), with an optional day in a separate field and no clock-time fields. ISO `YYYY-MM` input is also accepted and reformatted. Each journey remembers its builder dates for subsequent segments and places, including after reload; a new journey starts blank. The first departure date also fills the arrival date, which can then be changed independently. Editing or replacing a saved route does not overwrite these defaults. Dates can still be left blank. The same controls are used for saved places, edits and route replacement. Month precision is preserved in local storage, KML/KMZ and GeoJSON; no day or timezone is invented. Invalid calendar days and definitely reversed ranges are rejected; a month-only end may include a start day within the same month. Existing imported timestamps are preserved when only a name or note changes, while dates are shown without times in the itinerary and printed route list. Car segments also accept an optional model or vehicle name, retained in local storage and KML metadata; the next segment keeps the selected transport and car name.
- The left notebook can be pinned open, collapsed to an icon rail, or hidden and reopened with the map’s menu icon. Unpinned notebooks float over the map and collapse on outside clicks. Layout preferences persist; phones expose the same controls. Play Journey, chronological checked-journey playback and Fit Map use circular accessible icon buttons. The itinerary section is capped at a responsive height (at most 600 px), with an internal scrollbar for the active route/place list; its heading, tabs and selection controls stay outside that scrolling area. Item edits preserve the list scroll position, and switching journeys starts at the top.
- **Play journey** starts the active journey from the beginning in itinerary order, with all ordinary and important pins hidden initially. The player’s Resume control continues a paused animation. The compact map player has a 42%-opaque background while text and controls remain readable. It can be hidden and reopened without interrupting playback. Its visibility persists. It provides an icon to exit playback, pause/resume, replay, a seek slider, 8 speed settings (1×–128×), with the equivalent distance per second in the chosen units and optional camera following. Dragging the map turns following off. Following updates the camera on each animation frame and paints the route/icon after the basemap, keeping the vehicle steady on screen. It preserves the current zoom across segment changes, seeking, pause/resume and replay; user zoom and rotation gestures remain available. Playback redraws the active journey from the start: the visible line ends exactly at the moving icon, finished segments remain, and future segments stay hidden. Seeking backward removes the later geometry; replay clears it and starts again. Flight paths retain dashed lines at 50% opacity in the map, animation and exports; their colored stroke has no overlapping opaque casing. Playback hides the static route overview first, including across a continuous queue of journeys. Only the traveled part of the active route, completed routes and reached points appear; exiting restores the notebook’s visibility settings. Cars, trains and hikers use upright side-view artwork above a continuously visible highlighted location point. The artwork mirrors for leftward travel and gently flashes every 1.1 seconds independently of playback speed; paused playback and reduced-motion preferences keep it steady. Planes retain their heading-following artwork and two fading engine trails beside the dashed route. The route ends at the exact location point. Plane trails stop at globe horizons or world seams. Animation timing is a visual preview, independent of the itinerary’s stored dates. At 1×, cars move at 10 km/s, trains at 15 km/s, walking at 5 km/s and planes at 30 km/s along the displayed route. Default ratios are car 1×, train 1.5×, walking 0.5×, plane 3× and public transport 1×. Settings → Transport speeds adjusts each non-car ratio from 0.05× to 20×, using car as the fixed reference; the values persist locally and apply equally to map playback and video export. Updating a ratio keeps the current segment and location. Ratios remain the same at every playback rate, with duration proportional to distance and no per-segment minimum or maximum duration. Point arrivals, progress and exported video use these same segment durations. Distance follows the displayed Mercator line, including sparse high-latitude legs. The 1×–128× controls multiply the current transport’s base speed; speed labels follow the current segment; changing speed does not restart or jump the journey. Independent pins are excluded and gaps between segments are not connected. Editing a route resets playback; switching the active journey resets single-journey playback; switching map themes or projections retains it. At completion or explicit exit, playback cancels its animation frame, drops projected paths and restores the static map layers. Idle/finished map renders do not project or repaint the animation routes; this prevents very large routes from slowing later navigation. Playback also works in the 2D canvas fallback and pauses when the page is hidden. Hidden itinerary segments are omitted from playback.
- **Export animation video** is available in Export map & routes and through the camera icon in the map player. It exports checked journeys and their visible route segments in chronological order to silent H.264 MP4 with selectable 720p, 1080p, 1440p or 2160p (4K) resolution and 24, 25, 30, 50 or 60 fps. Defaults are 1080p / 30 fps. Landscape uses 16:9, portrait uses 9:16. Changing resolution preserves the composition and relative map, label and vehicle sizes. The chosen frame rate controls encoded timestamps and track metadata; bitrate scales with resolution and frame rate. Quality controls lock during export, settings remain selected when reopening the window, and downloads include resolution and fps in the filename. It snapshots the current theme (including imagery), projection, pitch, bearing, zoom, playback speed and Follow setting. The aspect ratio changes the horizontal crop while retaining the vertical map scale. Follow moves the export camera along the route; turn it off for a fixed view. All journey points start hidden and reveal only as the route reaches them. A seekable preview uses exactly the same renderer and frame dimensions as the video. The ground icons are 60% of their previous size (car/walk 38.4 px, train 43.2 px in logical map coordinates); planes are unchanged. Each video frame uses an explicit timestamp, so slow tile loads or encoding do not alter the route speed or skip time. Encoding runs on a separate map and leaves the live camera and notebook unchanged. Completed paths stay in static layers; only the current segment is redrawn. Progress, cancellation, a playable result and repeat download are provided. MP4 requires a browser with an H.264 WebCodecs encoder (checked before export); otherwise the window explains the limitation. Use HTTPS or localhost. Long outputs stream into a temporary browser-private file when available; the completed file is streamed into an independent browser-managed Blob for download, then the temporary file is deleted. Cancellation also deletes the temporary file. If private storage is unavailable, small outputs use memory, with a 256 MiB estimated limit. All encoding is local; existing basemap tile requests still use their map providers.
- During playback, all journey points start hidden, including ordinary endpoints, saved places and points from other journeys. Endpoints reveal at their segment boundaries; independent places reveal at the first route pass within 75 m. Later visits trigger a fresh callout, including a round trip ending at its starting point; the permanent marker is still drawn only once. Unreached places remain hidden until playback is exited. Gaps never count as travel. A star pops with a 1.6-second expanding ring and a name label; names show only the most specific place name (the first address component), stay fully visible for 2 playback seconds and fade out smoothly over the next second; the point markers remain. Pausing freezes the label clock, and changing speed does not restart a visible label. Seeking backward or replaying resets arrivals, and exiting restores static pins. Reduced-motion mode retains the star and label without the pulse/pop. Live playback and MP4 use the same arrival painter; videos hold the final frame long enough for the last visible name to finish fading (up to 3 seconds).
- **Play checked journeys by date** (the circular list/play icon beside Play Journey) continuously plays the journeys checked in the journey list. It sorts each journey’s visible routes chronologically and orders journeys by their earliest route date. Recorded start/track/end times take precedence, followed by recognizable dates in route names or imported folder names; a journey name date is used if no route has a date. Undated journeys play last in their existing order. Saved dates and itinerary ordering are unchanged. Hidden journeys, hidden segments and standalone places are excluded. The player shows the current journey name and queue position; pause, speed, follow, seeking, replay and exit apply to the whole queue. Future journeys stay hidden until playback reaches them, and completed segments return to static map layers immediately to avoid accumulating expensive animation overlays. Plane/car/train/walking effects and each journey’s color are retained.
- Flight segments and flight route previews use dashed lines in Journey Studio, including the canvas fallback. KML retains the continuous original geometry and transport metadata; importing it into Journey Studio restores the flight styling.
- Each itinerary item has an independent eye toggle for visibility and a selection checkbox for highlighting. Select multiple items across the route/place tabs, then use Export selected; each row also has a single-item export icon. Selection and visibility are independent, and visibility persists. Full-journey file export retains hidden items; the map export’s Checked journeys scope uses visible items.
- Add points through place search, latitude/longitude input or a map click. Route segments and independent saved places appear in keyboard-accessible Route segments / Saved places tabs and reorder within their own collection. The two tabs preserve independent points and routes in KML. Standalone pins never become route vertices. Both collections are exported together in separate KML folders. Edit coordinates, importance, notes and dates; reorder or remove entries. “Replace route” searches new geometry without removing the old segment until confirmed.
- The circular import and review/export icons beside the journey name support **KML, KMZ and GeoJSON**, plus ZIP imports. Import accepts multiple files in one selection, including ZIPs mixed with ordinary journey files. ZIPs are scanned through subfolders for KML, KMZ, GeoJSON and JSON entries; each supported entry becomes one journey, while a KMZ inside the ZIP remains one journey. Unrelated files and macOS resource-fork entries are ignored. ZIP input and expansion are limited to 50 MiB, with at most 1,000 entries and 10 MiB per journey file. Nested KMZ expansion shares the archive budget; extraction is streamed and bounded. ZIPs inside ZIPs are not recursively unpacked. Each successful file creates a separate journey in selection order with its saved color and video title; existing journeys remain unchanged. Files are parsed sequentially, and an invalid file does not prevent the others from importing. The progress and result panel identifies failed files and import warnings. The first successfully imported journey opens for editing; selecting the same file again creates another independent journey. KML Point, LineString, MultiGeometry and timed `gx:Track` data, plus GeoJSON Point/MultiPoint, LineString/MultiLineString and GeometryCollection members are editable. Coordinates, altitudes, modes, vehicle names, times, important nodes, custom properties and visibility survive format round trips. KMZ exports contain `doc.kml` and local PNG icons. Files are limited to 10 MiB; KMZ expanded contents are limited to 50 MiB / 1,000 entries and KML decompression is bounded. Unsupported geometries are reported. Original source files, including styles, folders and icon assets, are retained as a compressed base64 source archive in item metadata (already archived Studio files are not duplicated). Full exports retain that archive; partial exports omit whole-source archives so unselected routes are not included as backup data. The app renders its own styles and exports editable geometry in route/place collections.
- Road alternatives come from the public OSRM service, using additional road-network detours when fewer than three alternatives are returned. The editor seeks 3–5 distinct choices; some locations have fewer, and the UI reports the actual count. No routes or durations are invented when the service fails.
- Plane and train options are explicitly labeled **planning sketches** via suggested geographic hubs. They are not flight availability, rail-track paths, booking information or verified connecting services. Import an actual route KML when exact train/flight geometry matters. Road durations are estimates without live traffic.
- Place search uses [Photon](https://github.com/komoot/photon#demo-server), showing suggestions after two characters and a 300 ms typing pause. Arrow keys and Enter select a result; Escape dismisses it. Chinese/other IME composition is respected, stale searches are cancelled, results are cached, and requests are serialized at no more than one per second. The magnifying-glass button remains available with localized accessible labels. Photon and OSRM are public demo services with no availability guarantee, intended here for occasional personal planning. Map tiles, geocoding and road routing require internet access. Editing, KML processing and the locally bundled park poster assets do not require third-party services once the page is loaded.

- The header gear opens **Settings**, with English/中文 and metric/imperial segmented toggle buttons. New notebooks default to imperial units; saved unit preferences are retained. Both preferences persist; Chinese UI displays Wanderlust as **玩嘚儿了~** in a locally bundled handwritten font with an orange tilde. Saved journey names, notes and custom poster titles remain unchanged. Units also update the live map scale without changing KML coordinates.
- Transport uses a coordinated set of original flat SVG illustrations in radio cards for Car, Train, Plane, Walk and Public transport. Public transport uses a bus icon in both the picker and animation; its mode is retained in KML, KMZ and GeoJSON. New public transport routes are explicitly labeled geographic planning sketches, without route-network or timetable verification. Imported transit geometry is retained unchanged. Walking uses the [FOSSGIS pedestrian routing service](https://routing.openstreetmap.de/about.html), with queued requests at no more than one per second. It never substitutes a driving route when walking fails. Walking metadata survives KML import/export.
- **Journey colors** provides Trail tones, Coastal, Sunset and Vivid palettes, plus **Single color** with one picker that recolors every journey. New empty journeys inherit the chosen single color; individual overrides remain available and persist until another palette or shared color is applied. Each journey also has its own picker. Use the journey-list checkboxes to show any subset together. Colors are used on the map and stored in Journey Studio KML metadata and line styles.
- Settings contains all map preferences. **Minimal** is the default for new notebooks and older notebooks without a valid saved theme; an existing saved theme choice is retained. Available maps: [OpenFreeMap](https://openfreemap.org/quick_start/) Classic, Minimal, Bright and Night themes, NASA Blue Marble satellite imagery (with optional place labels), USGS US topographic maps, and 2D, 3D or Globe views. NASA imagery is a global overview at approximately 500 m detail, not street-level aerial photography; USGS topographic coverage is focused on the US. Source credits appear on the map and in exported images. Raster maps support tilted/globe navigation but do not contain 3D buildings. Provider sources and attribution are in `data/SOURCES.md`. Globe uses the same MapLibre map and editable journey overlays, with drag/scroll navigation and an atmospheric backdrop; entering it zooms out to show the planet. 3D tilts the map, supports right-drag rotation and shows extruded buildings at close zoom where building data exists. Style changes preserve all journey overlays. Devices without WebGL retain a themed 2D canvas overview and disable 3D and Globe. The GRIND Lab logo sits beside the Journey Studio wordmark, separated by a vertical divider, and opens the lab website in a new tab. Circular return and Settings controls precede Bucket List at the right edge of the header.

### Saving

The editor automatically saves an editable `workspace.json` and one KML companion per journey in its browser-private `.wanderlust` directory (OPFS), with IndexedDB and localStorage backups. Reopen the **same origin, port and browser profile** to restore it automatically. Clearing site storage clears the browser copies.

In desktop Chrome or Edge, **Connect a local folder** opens the browser's directory picker. A `.wanderlust` hidden subdirectory is created inside the selected directory; existing Journey Studio notebooks are read and merged before saving. The selected folder and its `.wanderlust` subfolder are displayed and remembered alongside the directory handle. Browsers expose the selected directory name and relative descendants, not its full absolute disk path; the UI labels this distinction. On the next visit the folder is read automatically if the browser still grants access; otherwise the browser copy opens and a reconnect notice appears. No website can silently choose an arbitrary directory on the computer. Other browsers retain browser-local saving and KML download.

Each local folder contains `workspace.json` (including park selections) and `journey-<id>.kml` files. Deleting a journey removes it from the notebook but leaves previously exported KML copies. Export KML to keep a separate portable backup. The page does not upload your saved notebooks; search queries and endpoint coordinates are sent to the public search/routing providers only when using those features.

### Inset maps and additional validation

Export map & routes supports up to three inset maps. Each inset has a title, coordinate center, zoom, size and corner placement; presets include the current main-map view, Alaska, Hawaii and the contiguous US. Dragging or scrolling inside an inset changes only that inset; the parent map retains its composition. Insets use the same basemap, selected routes and points, rendered in 2D for regional detail even when the parent is a globe. Preview/download reuse the same renderer and cameras, increasing only the pixel ratio. Insets are part of JPG/PNG output; file exports contain the geographic data rather than poster layouts.

**Route list beside map** adds a left or right column to posters or map-only images. The list follows the selected export scope and groups segments by journey, with matching colors, full route names, transport, car names, distances in the chosen units and recorded dates. It wraps long names and uses two columns for longer lists. If the complete list cannot fit, export reports the problem rather than silently omitting routes. The list is included in both JPG and PNG. Map dragging, inset placement and full-resolution downloads use the same map frame as the preview.

The map's **Show my location** crosshair button requests location once per click and centers a blue dot with an accuracy circle. Accuracy is shown in the chosen units; the position survives basemap changes and works in native 2D/3D/globe and the canvas fallback. Locating pauses playback and releases camera follow. Permission-denied, unavailable and timeout messages allow another attempt. Location requires HTTPS or localhost and browser/device permission. It is kept only for the current page session, is not added to journeys or saved places, and is excluded from route files and map images. There is no automatic location request or continuous tracking.
