# Bing Zhou website

Static HTML, CSS and JavaScript, suitable for GitHub Pages. No build or server-side API keys are required.

## Local preview

From this directory, run `python3 -m http.server 8770 --bind 127.0.0.1` and open <http://127.0.0.1:8770/>. Journey Studio is at `/journey-studio.html`, also linked from Wanderlust. Use HTTP/HTTPS, not `file://`, because the site uses JavaScript modules and local data fetches.

## Journey Studio

- The journey list shows every saved journey with its color, a visibility checkbox, an edit-name button and a delete icon. Click the name to edit that journey; independently check any subset to show on the map. All/None controls change visibility together. Hidden journeys remain editable and saved, and their playback is stopped/hidden. Deletion asks for confirmation; removing the last journey creates an empty one. Previous all/current-only map preferences migrate to per-journey visibility.
- Create multiple journeys, search/select endpoints or choose them using the crosshair icons beside Starting point and Destination (Escape cancels), compare route options and append segments. Every segment can have car, train, plane or walking metadata, important endpoints, notes and departure/arrival times. Car segments also accept an optional model or vehicle name, retained in local storage and KML metadata; the next segment keeps the selected transport and car name.
- The left notebook can be pinned open, collapsed to an icon rail, or hidden and reopened with the map’s menu icon. Unpinned notebooks float over the map and collapse on outside clicks. Layout preferences persist; phones expose the same controls. Play Journey, chronological checked-journey playback and Fit Map use circular accessible icon buttons. The itinerary section is capped at a responsive height (at most 600 px), with an internal scrollbar for the active route/place list; its heading, tabs and selection controls stay outside that scrolling area. Item edits preserve the list scroll position, and switching journeys starts at the top.
- **Play journey** animates the active journey’s route segments in itinerary order. The compact map player has a 42%-opaque background while text and controls remain readable. It can be hidden and reopened without interrupting playback. Its visibility persists. It provides an icon to exit playback, pause/resume, replay, a seek slider, 0.5×–4× speed and optional camera following. Dragging the map turns following off. Following updates the camera on each animation frame and paints the route/icon after the basemap, keeping the vehicle steady on screen. It preserves the current zoom across segment changes, seeking, pause/resume and replay; user zoom and rotation gestures remain available. Playback redraws the active journey from the start: the visible line ends exactly at the moving icon, finished segments remain, and future segments stay hidden. Seeking backward removes the later geometry; replay clears it and starts again. Flights retain dashed lines. Other journeys and independent points remain visible according to the map settings. Original illustrated vehicles follow the route heading: cars have subtle headlights, trains pull carriages, planes leave two fading engine trails beside the dashed route, and hikers leave footsteps. Effects follow the original route vertices, stay a consistent screen length at different zoom levels, and stop at globe horizons or world seams. Animation timing is a visual preview, independent of the itinerary’s stored dates. Independent pins are excluded and gaps between segments are not connected. Editing a route resets playback; switching the active journey resets single-journey playback; switching map themes or projections retains it. At completion or explicit exit, playback cancels its animation frame, drops projected paths and restores the static map layers. Idle/finished map renders do not project or repaint the animation routes; this prevents very large routes from slowing later navigation. Playback also works in the 2D canvas fallback and pauses when the page is hidden. Hidden itinerary segments are omitted from playback.
- **Play checked journeys by date** (the circular list/play icon beside Play Journey) continuously plays the journeys checked in the journey list. It sorts each journey’s visible routes chronologically and orders journeys by their earliest route date. Recorded start/track/end times take precedence, followed by recognizable dates in route names or imported folder names; a journey name date is used if no route has a date. Undated journeys play last in their existing order. Saved dates and itinerary ordering are unchanged. Hidden journeys, hidden segments and standalone places are excluded. The player shows the current journey name and queue position; pause, speed, follow, seeking, replay and exit apply to the whole queue. Future journeys stay hidden until playback reaches them, and completed journeys return to static map layers to avoid accumulating expensive animation overlays. Plane/car/train/walking effects and each journey’s color are retained.
- Flight segments and flight route previews use dashed lines in Journey Studio, including the canvas fallback. KML retains the continuous original geometry and transport metadata; importing it into Journey Studio restores the flight styling.
- Each itinerary item has an independent eye toggle for visibility and a selection checkbox for highlighting. Select multiple items across the route/place tabs, then use Export selected; each row also has a single-item export icon. Selection and visibility are independent, and visibility persists. Full-journey file export retains hidden items; the map export’s Checked journeys scope uses visible items.
- Add points through place search, latitude/longitude input or a map click. Route segments and independent saved places appear in keyboard-accessible Route segments / Saved places tabs and reorder within their own collection. The two tabs preserve independent points and routes in KML. Standalone pins never become route vertices. Both collections are exported together in separate KML folders. Edit coordinates, importance, notes and dates; reorder or remove entries. “Replace route” searches new geometry without removing the old segment until confirmed.
- The circular import and review/export icons beside the journey name support **KML, KMZ and GeoJSON**. KML Point, LineString, MultiGeometry and timed `gx:Track` data, plus GeoJSON Point/MultiPoint, LineString/MultiLineString and GeometryCollection members are editable. Coordinates, altitudes, modes, vehicle names, times, important nodes, custom properties and visibility survive format round trips. KMZ exports contain `doc.kml` and local PNG icons. Files are limited to 10 MiB; KMZ expanded contents are limited to 50 MiB / 1,000 entries and KML decompression is bounded. Unsupported geometries are reported. Original source files, including styles, folders and icon assets, are retained as a compressed base64 source archive in item metadata (already archived Studio files are not duplicated). Full exports retain that archive; partial exports omit whole-source archives so unselected routes are not included as backup data. The app renders its own styles and exports editable geometry in route/place collections.
- Road alternatives come from the public OSRM service, using additional road-network detours when fewer than three alternatives are returned. The editor seeks 3–5 distinct choices; some locations have fewer, and the UI reports the actual count. No routes or durations are invented when the service fails.
- Plane and train options are explicitly labeled **planning sketches** via suggested geographic hubs. They are not flight availability, rail-track paths, booking information or verified connecting services. Import an actual route KML when exact train/flight geometry matters. Road durations are estimates without live traffic.
- Place search uses [Photon](https://github.com/komoot/photon#demo-server), showing suggestions after two characters and a 300 ms typing pause. Arrow keys and Enter select a result; Escape dismisses it. Chinese/other IME composition is respected, stale searches are cancelled, results are cached, and requests are serialized at no more than one per second. The magnifying-glass button remains available with localized accessible labels. Photon and OSRM are public demo services with no availability guarantee, intended here for occasional personal planning. Map tiles, geocoding and road routing require internet access. Editing, KML processing and the locally bundled park poster assets do not require third-party services once the page is loaded.

- The header gear opens **Settings**, with English/中文 and metric/imperial segmented toggle buttons. New notebooks default to imperial units; saved unit preferences are retained. Both preferences persist; Chinese UI displays Wanderlust as **玩嘚儿了~** in a locally bundled handwritten font with an orange tilde. Saved journey names, notes and custom poster titles remain unchanged. Units also update the live map scale without changing KML coordinates.
- Transport uses locally bundled Phosphor duotone icon radio cards for Car, Train, Plane and Walk. Walking uses the [FOSSGIS pedestrian routing service](https://routing.openstreetmap.de/about.html), with queued requests at no more than one per second. It never substitutes a driving route when walking fails. Walking metadata survives KML import/export.
- **Journey colors** provides Trail tones, Coastal, Sunset and Vivid palettes, plus **Single color** with one picker that recolors every journey. New empty journeys inherit the chosen single color; individual overrides remain available and persist until another palette or shared color is applied. Each journey also has its own picker. Use the journey-list checkboxes to show any subset together. Colors are used on the map and stored in Journey Studio KML metadata and line styles.
- Settings contains all map preferences: [OpenFreeMap](https://openfreemap.org/quick_start/) Classic, Minimal, Bright and Night themes, NASA Blue Marble satellite imagery (with optional place labels), USGS US topographic maps, and 2D, 3D or Globe views. NASA imagery is a global overview at approximately 500 m detail, not street-level aerial photography; USGS topographic coverage is focused on the US. Source credits appear on the map and in exported images. Raster maps support tilted/globe navigation but do not contain 3D buildings. Provider sources and attribution are in `data/SOURCES.md`. Globe uses the same MapLibre map and editable journey overlays, with drag/scroll navigation and an atmospheric backdrop; entering it zooms out to show the planet. 3D tilts the map, supports right-drag rotation and shows extruded buildings at close zoom where building data exists. Style changes preserve all journey overlays. Devices without WebGL retain a themed 2D canvas overview and disable 3D and Globe. The GRIND Lab logo sits beside the Journey Studio wordmark, separated by a vertical divider, and opens the lab website in a new tab. Circular return and Settings controls precede Bucket List at the right edge of the header.

### Saving

The editor automatically saves an editable `workspace.json` and one KML companion per journey in its browser-private `.wanderlust` directory (OPFS), with IndexedDB and localStorage backups. Reopen the **same origin, port and browser profile** to restore it automatically. Clearing site storage clears the browser copies.

In desktop Chrome or Edge, **Connect a local folder** opens the browser's directory picker. A `.wanderlust` hidden subdirectory is created inside the selected directory; existing Journey Studio notebooks are read and merged before saving. The selected folder and its `.wanderlust` subfolder are displayed and remembered alongside the directory handle. Browsers expose the selected directory name and relative descendants, not its full absolute disk path; the UI labels this distinction. On the next visit the folder is read automatically if the browser still grants access; otherwise the browser copy opens and a reconnect notice appears. No website can silently choose an arbitrary directory on the computer. Other browsers retain browser-local saving and KML download.

Each local folder contains `workspace.json` (including park selections) and `journey-<id>.kml` files. Deleting a journey removes it from the notebook but leaves previously exported KML copies. Export KML to keep a separate portable backup. The page does not upload your saved notebooks; search queries and endpoint coordinates are sent to the public search/routing providers only when using those features.

### Bucket List

Choose **National parks**, **US states**, or **Combined**. Combined mode shows both checklists, state shading and park tree markers together; the two visited collections stay independent. The park collection uses the current NPS list, including Alaska, Hawaii, American Samoa and the US Virgin Islands. The state collection contains all 50 states (DC and territories are excluded). Each collection keeps its own visited selections and poster title.

Four templates are available for both collections: **Field notes** (topographic journal), **After dark** (celestial cartography), **Postcard** (vintage travel print), and **Modern atlas** (editorial design). The locally rendered JPEG includes the entire checklist in **portrait (4800 × 6000)** or an independently composed **landscape (6000 × 4800)** layout. Both orientations support all four templates and all three modes. Downloads render at twice the former width and height; the preview stays smaller for responsiveness. Preview with mouse-wheel zoom, left/middle-button drag, double-click zoom (Shift to zoom out), touch pinch, the +/− controls, arrow keys, and Home/Fit to reset. Preview transforms never affect export resolution. Chinese UI also localizes poster decoration and legends while retaining official place names. Park prints use green visited trees and gray unvisited trees; state prints fill visited states and include Alaska/Hawaii insets. Template, collection and orientation preferences persist across visits. The local brand font and transport icon licenses and sources are in `fonts/` and `images/journey-icons/`. Names and boundaries are documented in [data/SOURCES.md](data/SOURCES.md).

### Research samples, park overlay and map downloads

**Settings → Load test data** adds six editable example journeys without removing existing work. Repeated loads do not duplicate or overwrite already loaded examples. The collection includes Olson's published 2026 driving-time optimized loop through 52 lower-48 national park gateways, all 64 NPS national park overview points, four official Amtrak corridors (California Zephyr, Empire Builder, Southwest Chief, Lake Shore Limited), and CLL→LAX, LAX→SEA and JFK→STL great-circle flight examples. The park loop is a minimum-driving-time source result, not a globally shortest-distance itinerary covering all 64 parks. Island access and parks outside the lower48 require other transport; rail source gaps remain separate lines and flight arcs are examples rather than actual flights. Sources, geometry processing and licenses are in [data/JOURNEY_SAMPLES_SOURCES.md](data/JOURNEY_SAMPLES_SOURCES.md).

The circular **tree icon** on the map (accessible name: National parks) shows/hides all park markers independently of saved itinerary points. The preference survives reloads and theme changes; native map markers open white-background popups with official park links. A 2D canvas overview also draws the markers.

The circular **download** button immediately before Settings opens **Export map & routes**. Choose checked journeys (the default), the active journey, or all journeys; portrait/landscape; a decorated poster or map-only output; selected-journey bounds or the current view; saved places and park markers. Three template thumbnails show the Field notes, After dark and Modern atlas styles. **Map composition** adjusts the actual exported camera scale (50–400%) and horizontal/vertical placement. In **Arrange map**, drag within the map frame, scroll/double-click to scale, use arrow keys to position, or Home/Reset composition to reset; the same controls work in native 2D/3D/globe and the canvas fallback. **Inspect poster** retains the independent Bucket List-style preview gestures, which do not change the export. Drag and scroll updates are coalesced into animation frames on one persistent renderer, with cursor-anchored wheel zoom and no debounce/rebuild per gesture. JPG/PNG export increases only that renderer’s pixel ratio, retaining its logical dimensions, center, zoom, pitch, bearing and padding. It does not read a changed main-map camera or refit the bounds. Composition changes carry into JPG/PNG at full resolution and can crop the image; KML retains complete geometry. No checked journeys disables export until a journey or another scope is selected. JPG and PNG downloads are **4800×6000** or **6000×4800** and render the selected journeys independently of animation progress. KML includes all selected routes and saved places even when place markers are hidden from the image, with separate journey folders and unique styles. Native exports reuse the current basemap theme/view in a renderer retained until the export dialog closes; unavailable WebGL/initial renderer setup falls back to an explicitly labeled local 2D overview. Output credits remain in the image.

## Verification

With the preview server running, use a local Playwright installation:

```sh
node --test tests/journey-studio.test.cjs
```

Set `STUDIO_URL` for a different preview address. Set `CHROME_PATH` to use an installed Chrome executable, and `NODE_PATH` if Playwright is supplied by a separate runtime. Tests cover UI editing, validation, route selection, KML round trips, persistent storage, directory-handle synchronization, JPEG export, mobile layout and the non-WebGL map fallback. Additional coverage checks autocomplete races and keyboard selection, units, independent point/route ordering, legacy notebook migration, state selections and all eight collection/template combinations. Settings language persistence, icon radio selection, pedestrian routing, journey palettes and KML colors, map theme/view changes, landscape dimensions and preview gestures are also covered. Playback tests cover transport effects and controls, route-data immutability, date-line interpolation, separate segment boundaries, car metadata, flight styling, theme/globe transitions and the canvas fallback. Journey-list checks cover independent editing and visibility, cancel/confirm deletion, empty-notebook recovery, legacy visibility migration, single-color palettes and per-journey overrides. Composition checks cover template thumbnails, direct map dragging/scaling, separate poster inspection, full-resolution output and checked-journey KML selection. New coverage checks idempotent research-sample loading, national-park overlay persistence and popups, combined park/state checklists, doubled JPEG/PNG dimensions, and multi-journey KML export in both native and canvas map modes. Network fixtures make the regression tests repeatable; real provider availability is checked separately.

Live-export regression checks compare preview and full-resolution camera/landmark framing in 2D, 3D, Globe and the canvas fallback, verify preview updates during pointer-down without replacing the renderer, and check cleanup. Additional checks cover sidebar pin/collapse/hide persistence, tab keyboard navigation, playback while its controls are hidden, and imagery/topographic source changes preserving routes and parks.


### Inset maps and additional validation

Export map & routes supports up to three inset maps. Each inset has a title, coordinate center, zoom, size and corner placement; presets include the current main-map view, Alaska, Hawaii and the contiguous US. Dragging or scrolling inside an inset changes only that inset; the parent map retains its composition. Insets use the same basemap, selected routes and points, rendered in 2D for regional detail even when the parent is a globe. Preview/download reuse the same renderer and cameras, increasing only the pixel ratio. Insets are part of JPG/PNG output; file exports contain the geographic data rather than poster layouts.

Regression coverage additionally checks three-format metadata round trips, KMZ resources, malformed/oversized archive rejection, item visibility/selection and partial exports, starting/destination map picks, zero animation-route redraws after finish/exit, and live inset positioning plus high-resolution output in WebGL and canvas modes. Actual source KMZs and a 245,251-coordinate combined trip were also imported for local QA; personal data is not bundled with the website.

Chronological playback coverage checks date/name ordering without changing stored data, queue transitions, duplicate item IDs across journeys, pause/replay/exit cleanup, and stable visual scale in 2D, globe and canvas modes. Globe scale assertions account for MapLibre’s latitude compensation rather than requiring a constant numeric zoom ([MapLibre 5.12 globe guide](https://github.com/maplibre/maplibre-gl-js/blob/v5.12.0/developer-guides/globe.md#zoom-behavior)). Further checks cover bounded itinerary scrolling on desktop/mobile, the icon-only parks control, white popup background and reduced player background opacity.
